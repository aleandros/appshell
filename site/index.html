01 / THE ESSENTIALS

Start where the
interesting work begins.

Every SaaS needs the same foundation.
This one comes with the connections made.

[↪]01

The whole account lifecycle.

Signup, email verification, password recovery, and confirmed email changes. Cookie sessions and single-use tokens, already wired.

identity / sessions / recovery
[♧]02

Teams are a first-class feature.

Multiple organizations, owner/admin/member roles, and email-bound invitations. Tenant access is enforced on the server.

organizations / roles / invitations
[$]03

A path from free to paid.

Free and Pro plans, seat entitlements, and optional Stripe Checkout and billing portal. Signed, idempotent subscription webhooks.

subscriptions / seats / stripe
[▦]04

A workspace with good defaults.

Responsive React screens, shared controls, and light, dark, and system themes. Loading, empty, and error states included.

react / semantic tokens / storybook
[↗]05

Email that survives a retry.

A transactional outbox, branded HTML and plain text, and Mailpit for local development. Resend or SES for production delivery.

outbox / mail / optional jobs
[✓]06

Guardrails in the repository.

Generated API types, Zod validation, architecture checks, and browser tests. A separate admin console and redacted change history.

contracts / checks / administration

03 / CHOOSE YOUR HOME

Your app. Your infrastructure.

The same features and business rules.
Pick the starting point that fits.

[▱]THE DEFAULT

Keep it together.

A containerized Rust API, React frontend, and mail worker backed by PostgreSQL. Start with Docker Compose; the included deployment tooling targets Render.

DockerPostgreSQLRender
Docker deployment guide ↗
[λ]FULLY SERVERLESS

Let AWS run it.

API Gateway and Lambda, DynamoDB persistence, SQS jobs, SES email, and S3/CloudFront for the frontend. Provisioned with AWS SAM.

LambdaDynamoDBAWS SAM
Serverless deployment guide ↗

Prefer Lambda with PostgreSQL? That works too. Choose storage when starting a new app; switching later requires a data migration.

Local setup mode
# your terminal 
git clone https://github.com/aleandros/appshell.git my-app
cd my-app
npm ci
npm run setup -- --mode docker --name my-app
docker compose up -d db api
npm run dev
↗ Open localhost:5173 Mailpit on :8025
# your terminal 
git clone https://github.com/aleandros/appshell.git my-app
cd my-app
npm ci
npm run setup -- --mode lambda --storage dynamodb --name my-app --region us-east-1
docker compose -f compose.dynamodb.yaml up -d
npm run dev
↗ Runs locally without an AWS account.

Setup saves configuration; it doesn’t provision cloud resources. Apple Silicon: add --architecture arm64 to serverless setup for native Lambda builds.
